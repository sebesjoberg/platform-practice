# tf-16 Module quality

The spoke module works, but only you know how to call it. Next quarter other teams will use it,
and in tf-19 it gets its own repo and version numbers. The CTO wants it to read like a
registry module: inputs that explain and check themselves, outputs callers can build on, honest
version constraints and a generated README.

## Deliverables

In `terraform/modules/spoke`:

- [ ] Every variable has a `description`. `env` is validated to `dev` or `prod`, and
      `address_space` to a /16 CIDR block (the subnet layout needs one). Validate more where it
      helps a caller, such as `prefix` or `hub.vnet_id`.
- [ ] Outputs, each with a `description`: `resource_group_name`, `vnet_id`, `vnet_name` and
      `subnet_ids` (a map from `app`, `pe`, `aca` to the subnet IDs). Phase 3 builds on them.
- [ ] The version constraints become lower bounds: `required_version = ">= 1.17"` and azurerm
      `version = ">= 4.81, < 5.0"` (the oldest version the module needs, capped below the next
      major release). The stacks keep their `~>` pins.
- [ ] A `README.md` with a short intro and usage example, and a section generated by
      `terraform-docs` between `<!-- BEGIN_TF_DOCS -->` and `<!-- END_TF_DOCS -->`.
- [ ] Ship it as a PR. Both env stacks plan `No changes.` Merge it.

## Done when

`./lab.sh grade` passes: every input and output is described, `env` and `address_space` are
validated, the constraints are `>=` lower bounds, the README lists every input and output, and
it is on `main` on GitHub.
